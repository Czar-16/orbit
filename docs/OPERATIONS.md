# Setup, commands and troubleshooting

Prerequisites: Ubuntu, Node >=24.11.1 <25, npm >=11, Docker with Compose v2, permission to run Docker, and free local ports (3000 app, 55432 database, 8288 Inngest). Use npm ci with the committed lockfile. The default clean setup is README.md; db:setup creates random private credentials and an empty workspace, not sample personal facts.

## Environment

| Variable | Meaning |
| --- | --- |
| ORBIT_MODE | local only (default) |
| DATABASE_URL | Optional until setup; credentialed loopback postgres/postgresql URL, database name, no query/hash |
| ORBIT_DB_PASSWORD | Dedicated Compose password; generated by db:setup, matches DATABASE_URL |
| ORBIT_SCHEDULER_ENABLED | true default; false disables startup/request dispatch for isolated acceptance |
| ORBIT_ALLOW_PAID_AI | false default; true permits explicit configured hosted selection |
| OPENAI_API_KEY / OPENAI_MODEL | Optional hosted selection credentials/model; neither needed for normal operation |
| OLLAMA_MODEL | Optional local model at fixed 127.0.0.1:11434 |
| NODE_ENV | Standard development/production/test; managed by Next/test scripts |

Use ignored .env.local; never print credentials or commit resumes. Startup validates env with Zod and reports field names without secret values. No source API keys or Inngest cloud credentials are required for the implemented public API/local scheduler path. Source toggles, preferences and daily caps live in the database, not env. ORBIT_TEST_DATABASE is reserved for disposable tests, not normal use.

## Commands and migrations

| Command | Purpose |
| --- | --- |
| npm ci | Install exact lockfile dependencies; generate Prisma client |
| npm run db:setup | Guarded dedicated Compose database startup, deploy migrations, initialize empty workspace |
| npm run db:generate / db:validate | Generate installed Prisma client / validate schema |
| npm run db:migrate | Deploy committed migrations to explicitly configured database |
| npm run dev | Generate Prisma then start loopback development app |
| npm run build / start | Generate/build / serve loopback production app |
| npm run inngest:dev | Local persistent runtime, explicit SDK registration on port 3000 |
| npm run lint / typecheck / test | ESLint / strict TS and generation / unit and DOM tests |
| npm run test:db | Disposable database integration and migration checks |
| npm run test:scheduler | Real local Inngest acceptance; ports 3178/8288 must be free |
| npm run test:clean-start | Fresh isolated installation/build/HTTP/database-restore acceptance |
| npm audit --omit=dev | Production dependency vulnerability check |

Ten committed migrations establish foundation, profiles, jobs, historical snapshots, weighted matching, discovery, preparation, tracking and scheduling (see prisma/migrations for exact names). Apply with migrate deploy; never reset the normal database. Back up before future migrations. Prisma config loads .env.local. For an existing loopback PostgreSQL instance, configure DATABASE_URL privately, run db:migrate and initialize Workspace key local as documented in DATABASE.md. db:setup deliberately refuses other targets. Restart the app after configuration/schema changes. No sample seed script exists; synthetic fixtures are confined to disposable tests and excluded from real metrics.

## Troubleshooting

- Not configured / workspace setup pending: run db:setup, then restart Orbit. Never enter made-up profile facts to clear a setup state.
- Connection unavailable: check Docker service and Compose postgres health without printing env; confirm port 55432 and apply migrations. Use the dedicated setup command rather than migration reset.
- Missing Prisma delegate after pulling: stop/restart dev (it generates the client); run db:generate if necessary. Cached clients are replaced when the generated constructor changes.
- Run queued / Inngest unavailable: start inngest:dev, verify the actual app port registration, then Run now. See SCHEDULING.md for alternate ports. Do not run two runtimes on 8288.
- Source failed / rate limited: inspect persisted summary; wait until the next Kolkata day. Failed/uncertain requests count; do not clear quotas to retry. Manual paste remains available.
- URL rejected: paste the description without a URL or correct the public HTTPS reference; never disable SSRF checks.
- PDF extraction fails: use readable PDF/UTF-8 TXT or manually review profile fields. No OCR/DOCX support. Original private file remains preserved.
- Optional AI unavailable: choose off/deterministic; no AI key is required. Provider failures do not create drafts or successful outbound logs.
- Export/download returns 403: open the same loopback host/port consistently; localhost and 127.0.0.1 are different browser origins. Foreign-origin requests are deliberately rejected.
- Build font/network failure: next/font requires initial Geist download; confirm network access. Never treat an interrupted build as a passing check.
- Restore: use a fresh isolated instance with the matching code/migrations/private files. BACKUP.md documents pg_dump/pg_restore. Never overwrite the live workspace as a test.

Local-only limitations: no remote auth, OS boot service, missed-day backlog, submission integration, follow-up notifications, resume removal/redaction or exported tailored PDF. Optional real AI providers and manual visual/keyboard acceptance remain unverified. See README.md for list/search/extraction bounds.
