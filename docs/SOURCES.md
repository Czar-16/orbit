# Source review — 2026-10-12

Scope: local personal job search only, no republication, no platform automation or submission. Source permission decisions below were recorded before adapters were enabled. The user waived approval waits through Phase 6, but not the permanent permission/compliance rules. API-specific express permission is used only for the documented interface, never for scraping other pages. Aggregated listings remain inferred with official-interface evidence, not verified employer facts.

## Enabled public APIs

- **Himalayas:** [official API permission and fields](https://himalayas.app/api), [general terms](https://himalayas.app/terms). API docs expressly allow internal dashboards and automation, providing the required interface-specific consent; general website restrictions do not authorize any other access. GET https://himalayas.app/jobs/api/search with country=IN, q from role preferences, recent sorting, and optional company slug. Free/no authentication. Rate limits exist but a numeric quota is not published: Orbit caps the provider at four calls per Kolkata day and each query at once/day; 429 is a stop, not bypassed. Search/browse records capped locally at 20 per request. India/worldwide restrictions are retained and prefiltered. Persist only selected local listings; no raw response archive or redistribution. Mention/link Himalayas and preserve applicationLink exactly. Listings are cached as local immutable revisions; public API docs recommend daily caching, but publish no numeric retention period. Delete locally if access permission is revoked. Conclusion: allowed for this scoped API-only internal dashboard use.
- **Remotive public API:** [official API terms](https://github.com/remotive-com/remote-jobs-api), [general/subscription terms](https://remotive.com/terms-of-use). GET https://remotive.com/api/remote-jobs with search and limit=20, optionally company_name. API-specific permission permits further job display with Remotive attribution and exact returned Remotive URL. No auth; 24-hour-delayed listings; advised at most four requests/day, excessive >2/minute blocked. Orbit uses at most four calls per Kolkata day, one per query/day, sequential provider requests with spacing. This is the public API, not subscription content; no paid data or signup wall. No forwarding to third-party job boards. Remote India/Worldwide descriptions prefiltered, geographic eligibility never inferred from “remote” alone. Local selected listing persistence only; no raw archive or redistribution. No numeric retention rule in the public API license; remove if permission revoked. Conclusion: allowed only for public API local personal use, with the required attribution/link-back.

- **Jobicy:** [official API documentation/fair-use rules](https://github.com/Jobicy/remote-jobs-api). GET https://jobicy.com/api/v2/remote-jobs; free/no key, public seven-day feed, 1–200 records/page. Expressly permits discovery products/internal applications and storing by ID; retain Jobicy attribution and canonical URL. Cache allowed; new sync passes no more than hourly. Orbit uses one query/day, count=20, role-derived tag and local India/Anywhere prefilter. Optional structured salary mapped only with supported period/currency. No raw archive, redistribution, or status inference from feed absence. Conclusion: allowed; public free endpoint only, no commercial wallet/API key.
- **Remote OK:** [official feed/aggregator permission](https://remoteok.com/faq), [general terms](https://remoteok.com/legal). GET https://remoteok.com/api?tag=dev; free/no key, requires source credit and original job-post link for aggregators. Retain the returned URL and source name, no logo use. Numeric rate/retention period not published; Orbit uses one query/day, four/provider/day maximum and only selected local rows. Remote does not establish India eligibility; local geography/role prefilters apply. Conclusion: allowed for the documented public feed; no subscription data, scraping, or paid functionality.
