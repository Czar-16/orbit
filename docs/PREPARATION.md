# Application preparation

Works without an AI key. Upload a private PDF/TXT, review and explicitly verify profile facts, and select a resume in Profile (or designate a default). Role labels help choose among resume versions; they do not assert personal qualifications or automatically change the selected version.

Click Prepare application on a visible job without hard-filter conflicts. The workflow loads current immutable job/profile/preferences and the selected private resume. A missing preference version gets a clearly labeled defaults snapshot. It saves a linked draft and opens review. Repeating the initial button opens the existing active draft; regeneration is explicit in review. Dismissed/archived jobs must be restored. Resolve hard-filter conflicts first.

Review the letter, answers, saved match explanation and original resume download. Unknown/sensitive/custom questions remain empty and say Needs your input. Add up to 20 employer questions during regeneration. Exact supported question labels are Full name, Email, Relevant skills and Education; alternate wording needs manual input. Unknown work authorization, compensation, availability and demographic/disability/veteran answers are never guessed. User-filled answers stay User-provided, not automatically verified.

Edit and confirm supported claims, then Save revision. Each save appends history and rejects stale tabs. Regeneration uses current profile/job/preferences, the chosen resume, and the chosen provider. It warns before abandoning unsaved edits. Discard confirms and appends a tombstone; earlier revisions remain accessible. Prepare again creates a new revision after discard. History is append-only at the SQL boundary and scoped to the workspace and exact job.

Resume emphasis is selection/order only. Only user-verified project bullets found verbatim (allowing PDF whitespace normalization) in the chosen extracted document qualify. Original eligible bullets retain resume order; recommendations prioritize overlapping confirmed skills. Supply comma-separated bullet numbers to choose/order them; empty omits all. No bullet text or uploaded byte is rewritten. This is a displayed recommendation, not a generated replacement PDF. Missing verbatim bullets or failed extraction are explicitly flagged; verified-profile letter drafting still works if extraction fails.

## Extraction review

unpdf 1.8.1 was selected after inspecting its [maintained official README](https://github.com/unjs/unpdf), published Node >=22 support and installed API. It bundles PDF.js and needs no separate paid service. PDF parsing runs in a separate Node process, with 128 MB V8 heap setting, 15-second deadline, 30-page and 100,000-character bounds, eval disabled, no secrets in the child's environment, and no logs containing document data. This bounds processing but is not an OS sandbox. UTF-8 TXT reads remain local and capped at 100,000 characters. Originals remain privately stored with existing 5 MB/type/path validation. There is no OCR, DOCX support or public storage.

Profile offers Extract text for review and Review proposed facts. Conservative proposals fill only missing email/skills/project-bullet fields, retain Inferred provenance and never persist until the existing form's explicit verification/save. No name, experience, degree, dates, legal answers, Java or Spring Boot skill is inferred. Bullet markers can occur in non-project sections, so users must review/remove such candidates. Extraction is transient, never an automatic overwrite. Proposal save uses the same stale-profile protection as manual entry.

## Optional AI and data handling

Default Off is local deterministic mode. Optional OpenAI/Ollama assistance is selected per regeneration. Configure an explicit `OPENAI_MODEL` and `OPENAI_API_KEY` plus `ORBIT_ALLOW_PAID_AI=true` to allow hosted spending, or `OLLAMA_MODEL` for a model already available at fixed loopback http://127.0.0.1:11434. No remote Ollama/custom endpoint is accepted. No models are downloaded automatically. Neither adapter has been exercised against a real provider in this phase; UI says untested. Mock protocol tests establish parsing/failure handling only. No paid call was made.

Adapters follow [official OpenAI Responses structured-output guidance](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) and [official Ollama Generate documentation](https://docs.ollama.com/api/generate). OpenAI uses `/v1/responses`, JSON object output and `store:false`; Ollama uses nonstreaming `/api/generate` with JSON format. Fixed endpoints, no redirects, 30-second timeout, bounded 128 KB response and Zod validation are enforced. No retry or fallback is presented as provider success.

AI may select/order indexes into allowlisted verified skill sentences/project sentences and existing eligible resume bullets. Arbitrary model prose, metrics, rewritten claims, answers and new facts are rejected. Job analysis, match explanation and supported answers remain deterministic; this phase deliberately limits supplementary AI to content selection rather than unconstrained drafting. Job descriptions are never sent or executed. Minimal supplied requirement skills are sent as inert JSON data and cannot create claims outside the allowlist.

OutboundDataLog is written before every provider attempt, including local calls. It stores feature, provider, model, UTC time, field names and attempted/succeeded/failed outcome. No raw document, email, name, sensitive answers, prompt, response, secret or key is logged. Requests send relevant verified skill sentences and project facts/verbatim eligible bullets, plus supplied requirement skills; no original file or full profile. Settings shows the latest 100 attempts. A crash can leave attempted; this is not success. OpenAI's `store:false` is not a promise about every provider retention policy.

Prepare/Review/Open original listing never submit or mark Applied. Authorized submission is disabled because no permitted integration is installed. Actual submission remains a user action on the employer's site. Tracking/follow-ups/export are Phase 7, scheduling/catch-up Phase 8.
